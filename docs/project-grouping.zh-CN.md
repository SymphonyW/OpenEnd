# 按项目查看进程和端口

进程页和端口页共用项目归属。在页面顶部切换“全部 / 按项目”，也可以用“筛选项目”只看一个项目。普通列表中也显示“所属项目”。项目通过完整目录区分，同名文件夹不会被合并。

分组显示项目路径、进程数、内存合计和监听 TCP / 已绑定 UDP 端口。合计只统计当前页面筛选后的成员；端口页同一进程的多个端口不会重复计算内存。无法核对端口所属进程时，归入“未分组”，相关合计标为不可用。

点击“查看该项目端口 / 查看该项目进程”可跨页查看。跳转时会清掉目标页的旧搜索条件，保留新的项目筛选。两个页面分别记住查看方式，自动刷新保留展开状态。

## 自动判断与手动修正

| 判断顺序 | 依据 |
| --- | --- |
| 1 | 当前这次运行的手动指定，以进程编号和创建时间共同确定身份 |
| 2 | 已保存的工作目录规则，较具体的目录优先 |
| 3 | 启动命令参数中的明确项目路径，程序本身的安装路径不作为依据 |
| 4 | 当前工作目录 |
| 5 | 已确认归属且创建时间有效的父进程 |

项目根目录优先采用最近的 Git 仓库根目录，因此同一仓库内的前后端会合并。没有 Git 时，查找最近的 `package.json`、`go.mod`、`pyproject.toml`、`Cargo.toml`、`pom.xml` 或 Gradle 标记。依赖目录中的包标记不单独创建项目。

多个命令参数指向不同项目时，保持未分组。已知编辑器、浏览器、终端、Docker 和 WSL 宿主不参与自动归属或父子关系传播。第一版不推断容器或 WSL 内部项目，不自动扫描网络共享目录；权限不足、目录不存在或缺少项目标记时，仍可能无法识别。

两个页面的详情中都能查看“归属依据”和“工作目录”，并修改项目目录。留空或点击“移出分组”可以取消归属。

- 默认只修改当前这次运行；相同进程编号被重新使用时不会继承旧修正。
- 勾选“以后也按这个工作目录归类”后，将规则保存到现有本地 SQLite 配置。规则覆盖该目录及子目录，包括未来启动的进程。
- “恢复自动判断”会清除本次运行的修正，并删除适用于该工作目录的已保存规则；这可能同时影响使用这些规则的其他进程，界面会显示提示。
- 分组不提供批量结束项目。现有结束操作仍需确认，并核对进程身份和保护规则。

## 本地验证

运行 `wails dev`，同时启动两个不同目录中的 Node / Python 项目，检查同名进程能否正确分开，再检查同一仓库的前后端能否合并。在进程页展开分组，跳转到对应端口页，并从任一页面修改归属，确认另一页面随之更新。

验证暂存修正、记住目录规则、移出分组和恢复自动判断。重启应用后，暂存修正应消失，已保存规则应保留。工作目录无法读取的进程仍可临时修正，但不能保存目录规则。

自动检查：`go test ./...`、`npm --prefix frontend test`、`npm --prefix frontend run build`。
