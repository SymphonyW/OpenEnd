# 应用与项目

进程页和端口页共用归属。在页面顶部切换“全部 / 应用与项目”，也可以用“筛选应用或项目”只看一个分组。普通列表显示“所属应用 / 项目”，分组标题用“应用”和“项目”标签区分类型。

项目通过完整目录区分，应用通过主程序的完整路径区分。同名项目、同名应用的不同安装目录，以及同名的应用组和项目组，都不会被合并。

分组显示归属路径、进程数、内存合计和监听 TCP / 已绑定 UDP 端口。合计只统计当前页面筛选后的成员；端口页同一进程的多个端口不会重复计算内存。无法核对端口所属进程时，归入“未识别归属”，相关合计标为不可用。

点击“查看端口 / 查看进程”可跨页查看当前分组。跳转时会清掉目标页的旧搜索条件，保留新的归属筛选。两个页面分别记住查看方式，自动刷新保留展开状态。

## 自动判断与手动修正

| 判断顺序 | 依据 |
| --- | --- |
| 1 | 当前这次运行的手动指定，以进程编号和创建时间共同确定身份 |
| 2 | 已保存的工作目录规则，较具体的目录优先 |
| 3 | 启动命令参数中的明确项目路径，程序本身的安装路径不作为依据 |
| 4 | 当前工作目录 |
| 5 | 已确认归属且创建时间有效的父进程 |

项目根目录优先采用最近的 Git 仓库根目录，因此同一仓库内的前后端会合并。没有 Git 时，查找最近的 `package.json`、`go.mod`、`pyproject.toml`、`Cargo.toml`、`pom.xml` 或 Gradle 标记。依赖目录中的包标记不单独创建项目。

项目归属优先，其次判断应用，最后保留“未识别归属”。自动项目识别面向开发运行环境和项目目录内的程序；普通应用仅仅从项目目录打开，或打开了项目内的文件，不会因此变成项目成员。多个开发命令参数指向不同项目时，保留未识别归属。

应用名称优先读取 Windows 程序描述，读取失败时使用常见名称或程序文件名。同一程序路径下的进程归入同一应用；安装目录内可确认的辅助进程跟随应用主进程，并核对父进程的创建时间。没有足够依据的独立辅助程序保持单独分组，不仅因为名字相同或父进程相同就合并。

例如，VS Code 的主进程、编辑器自身子进程和可识别的安装目录内辅助进程归入“Visual Studio Code”；它启动的、有明确项目归属的 Node 服务归入对应项目。找不到项目的 Node、Python、Java 等共享运行环境不会混成一个应用。终端、系统宿主、Docker 和 WSL 不作为吸收其他进程的应用组。

当前不推断容器或 WSL 内部项目，不自动读取网络共享程序的应用信息；权限不足、目录不存在或缺少项目标记时，仍可能无法识别。保护状态独立于归属，分组不会解除进程保护。

两个页面的详情中都能查看“归属依据”和“工作目录”。在“修改归属”中填写项目目录，可将进程关联到项目；留空或点击“移出分组”可以取消应用和项目归属。

- 默认只修改当前这次运行；相同进程编号被重新使用时不会继承旧修正。
- 勾选“以后也按这个工作目录归类”后，将规则保存到现有本地 SQLite 配置。规则覆盖该目录及子目录，包括未来启动的进程。
- “恢复自动判断”会清除本次运行的修正，并删除适用于该工作目录的已保存规则；这可能同时影响使用这些规则的其他进程，界面会显示提示。
- 分组不提供批量结束应用或项目。现有结束操作仍需确认，并核对进程身份和保护规则。

## 本地验证

运行 `wails dev`，同时打开浏览器、编辑器和两个不同目录中的 Node / Python 项目。检查应用自身进程能否合并、不同项目能否分开，以及同一仓库的前后端能否合并。在进程页展开应用和项目组，分别跳转到对应端口页，确认筛选和类型标签一致。

验证暂存修正、记住目录规则、移出分组和恢复自动判断。重启应用后，暂存修正应消失，已保存规则应保留。工作目录无法读取的进程仍可临时修正，但不能保存目录规则。

自动检查：`go test ./...`、`npm --prefix frontend test`、`npm --prefix frontend run build`。
